The prepared fail-closed backup/preflight command, from the repository root:
  node outputs/automotive-release-2026-10-19/deployment/snapshot-cloudflare-readonly.mjs
It reads an existing CLOUDFLARE_API_TOKEN environment variable or the existing
Wrangler OAuth access token privately. It never creates/refreshes credentials.
Each run creates a new deployment/snapshots/<UTC timestamp>.local directory with
exclusive file writes, so it cannot replace the earlier capture. The *.local
directory is ignored by Git because raw settings can contain private values.
Do not attach its raw configurations to a public report or commit them.

The command captures GET zone/account metadata, DNS, Worker routes/custom domains,
page rules, zone/account rulesets and redirect lists, relevant HTTPS settings,
active deployments, version history/details including bindings/settings, raw
code multipart/download, script settings, schedules and subdomain configuration.
Any missing permission, API error, unhandled pagination or state drift prevents a
complete snapshot. It identifies Workers from actual route/domain mappings rather
than assuming the repository Worker name is live. It verifies active deployments
and routes again at the end. A new read-only comparison is run with:
  node outputs/automotive-release-2026-10-19/deployment/snapshot-cloudflare-readonly.mjs --compare=<path-to-prior-complete-timestamp.local> --origin-state=<private-origin-evidence.json>

The private origin evidence must record host, publishedDeploymentId,
publishedSourceSha, rollbackTarget and verifiedAt from the actual published host.
Those fields are an evidence requirement, not a method to discover or fabricate
unknown IDs. The script fingerprints the captured remote base and compares it to
the prior complete capture; failure exits nonzero. It never sets releaseAllowed
to true because read-only evidence cannot authorize publication. Recheck the
reviewed candidate's baseline and source hashes independently against the captured
base before any future upload. Even a passed comparison needs a short publication
freeze, current origin verification and explicit approval; it is not an atomic
compare-and-swap deployment lock.

A complete executable rollback target was NOT obtained. Public HTML/headers and
the editor SHA are preserved, but they do not contain every live asset, binding,
rule or the immutable live deployment identifier. Do not claim that local HEAD,
the old PPF parent, or an archived router bundle restores the current production.

For the verified Lovable path, obtain and record the exact pre-release published
snapshot/commit and the supported recovery operation before GO. After approval,
restore that exact remote snapshot through the same host and republish, preserving
all pre-release PPF/tuning changes. Avoid working-tree reset/checkout/stash and
do not unpublish the site as a rollback.

If the actual content host is a Workers version with static assets, save the full
pre-release version and traffic split first. Cloudflare's supported single-version
rollback form is:
  npx wrangler rollback <pre-release-active-version-id> --name <verified-worker> --message "Restore pre-automotive-release version"
For a pre-existing split deployment, restoring only one version at 100% does not
restore the prior split. Restore the saved version percentages with versions
deploy instead. Rollbacks do not restore independent storage or routes. No
storage/route/config changes should be included in this automotive release.

After any rollback, compare all saved PPF and tuning rendered markers and contact
paths, the affected 30 EN/AR routes, sitemap, canonical/hreflang/schema and known
redirects to the captured pre-release state. Investigate any mismatch before
reopening release work.

Treat origin and edge as a recovery pair: record both immutable pre-release
states, declare which is changing, and keep the unchanged member pinned. For
this content-only release the edge remains unchanged while the approved Lovable
snapshot is promoted. A failed content release should restore that recorded
origin snapshot with the same edge. If unexpected edge drift is observed, stop
and restore only the exact recorded edge state after reviewing current traffic;
do not detach routes to return to an assumed historical origin. If the real host
uses Worker static assets, its saved version covers code/assets/bindings, while
the recorded routes/custom domains and any separate Lovable origin still require
verification. No verified origin or Worker rollback UUID is available now.
