Technical wording boundaries

Diagnostics investigates a reported fault with available data and relevant physical tests. A code or a noncommunicating module alone does not establish a failed ECU.
Coding configures supported settings for the vehicle/equipment. Programming writes compatible control-unit software. Reading data does not establish coding/programming availability.
Some component replacements require setup, coding, programming, validation or learned-value procedures. Not every replacement needs every procedure; the exact repair information and unit determine the work.
An adaptation/calibration is a separate setup/learned-value procedure in some cases. No new ADAS, ride-height or other specific calibration capability is asserted.
Model/year, module identification, software level, fitted equipment, hardware and permitted platform access affect support. Similar connectors or a used part's appearance do not establish suitability. Customers should discuss compatibility before buying.
A software update is not a universal electrical repair. Supply, wiring, communication and symptom findings determine the next step.
Performance remapping changes performance calibration; keep that task on /tuning. A tuning package does not prove OEM module-programming, hardware-repair or security capability.

Do not require a report or known part number to enquire. Ask for unnecessary personal details to be removed from reports. Do not request passwords, login codes, software credentials, security access data or immobilizer secrets. No VIN is required in the initial public draft.
