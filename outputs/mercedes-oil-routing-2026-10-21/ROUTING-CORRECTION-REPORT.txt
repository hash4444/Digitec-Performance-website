3. EXACT PROPOSED CHANGE

Add ONE Cloudflare Single Redirect to this existing zone. Do not replace the ruleset.
Rule file: proposal/single-redirect-rule.json.
Description: Mercedes oil change legacy URLs to existing service.

Expression:
(http.host in {"digitecme.com" "www.digitecme.com"}) and (http.request.method in {"GET" "HEAD"}) and (http.request.uri.path in {"/brands/mercedes-benz-service-dubai/oil-change" "/brands/mercedes-benz-service-dubai/oil-change/"})

Action: static redirect.
Target: https://digitecme.com/services/mercedes-oil-change-dubai
Status:308 Permanent Redirect.
Preserve query string:true.
Position:FIRST, before dbe42693423442afbc3bab9b993242a7.
Both existing rules remain unchanged and retain their relative order.

Affected sources: the two exact legacy paths, on apex/www, GET/HEAD, either scheme. No wildcard, prefix, case-folding or global path-normalization behavior is added. Mutations are excluded from the NEW rule; existing www/HTTPS handling still applies to them as before.

Example expected response:
  https://www.digitecme.com/brands/mercedes-benz-service-dubai/oil-change/?tag=a&tag=b&gclid=sample
  308 Location: https://digitecme.com/services/mercedes-oil-change-dubai?tag=a&tag=b&gclid=sample
  destination200 with existing service content.

Placing it first avoids the existing www rule causing a www-alias -> apex-alias -> service chain. The rule's target matches neither legacy source, so it creates no loop. Offline tests establish this within the observed Single Redirect model. Actual Cloudflare cross-phase behavior, including Always Use HTTPS, still requires post-activation verification; do not promise a one-hop HTTP result before that check.
