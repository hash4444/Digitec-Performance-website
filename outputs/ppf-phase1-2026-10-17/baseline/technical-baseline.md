## Checks that already pass at baseline

- Eight canonical owner URLs return HTTP 200 HTML with one clear H1, one unique title/description, a self-referencing canonical and `index, follow, max-image-preview:large`.
- All have reciprocal `en-AE`, `ar-AE` and `x-default` alternate relationships to the expected route pair. Initial HTML has the expected language.
- Substantial text is present in initial response HTML, not only in a client-rendered shell: 3,898–17,439 extracted characters across the eight samples. The custom EN PPF HTML contains 16,568 extracted characters; AR PPF 5,299.
- Route JSON-LD parses as JSON without errors. Main commercial pages include `WebPage`, `Service` and `BreadcrumbList`; shared entity nodes include `Organization`, `WebSite`, `AutoRepair`/`AutomotiveBusiness` and `OfferCatalog`. Comparison pages use `BlogPosting` and breadcrumbs. This is syntax/content inspection, not Google's external Rich Results validation.
- FAQ schema is present on AR PPF and EN comparison; absent FAQ schema on EN PPF and AR comparison is not itself a technical error. Rich-result availability is not promised.
- Canonical EN PPF hero is WebP, has 1200×1200 dimensions and high fetch priority; the workshop image has dimensions and lazy loading. No new imagery was generated or customer-project provenance inferred by this audit.
- Homepage, Services, EN polishing and the comparison already provide crawlable PPF links; EN and AR home/services links point to their respective locale owners. Therefore, the primary PPF page is not an orphan in the sampled architecture.
- `http://digitecme.com` and `https://www.digitecme.com` PPF EN/AR samples each permanently redirect with a single 301 to the HTTPS apex canonical, then return 200.
- `robots.txt` and `sitemap.xml` return 200. Sitemap contains 1,005 URLs. Robots allows public crawling, retains `/wp-admin` and `/wp-login` disallows, and points to the expected sitemap. Existing explicit OpenAI crawler rules were observed and not changed; no new AI-specific directives are needed.

The production script builds `src/entry-server.tsx`, synchronizes route paths, builds the client, rebuilds the server bundle, then runs `scripts/prerender.mjs` and generated-hosting/SEO validations. `prerender.mjs` writes real route HTML and canonical/hreflang/JSON-LD metadata.
