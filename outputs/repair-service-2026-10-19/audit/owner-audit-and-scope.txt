Metadata decisions
The BMW transmission owner has the clearest English metadata gap: its description is the shared template ("BMW transmission repair in Dubai with model-specific inspection, confirmed parts options and a clear quote at Digi-Tec, Al Quoz."). It omits the delayed engagement, rough shifts, slipping and gearbox-warning concerns already explained in its body. A description using those existing symptoms is justified. Existing English titles/descriptions on the other owners already describe the repair intent, Dubai/Al Quoz and diagnosis-first scope. Change them only where a concrete improvement in intent or booking clarity is shown; demand alone does not justify churn. The full exact baseline is in the CSV.

Content and conversion findings by owner group
1. Mercedes engine/suspension/diagnostics/transmission: English pages already contain substantial symptom-to-test explanations, inspection steps, quote boundaries and relevant problem guides. Arabic pages already have service-specific overrides and should retain them. Do not duplicate the existing technical explanation. A compact service-specific appointment checklist is useful, particularly engine/transmission WhatsApp prefills, which currently contain only a generic service enquiry. Existing suspension/diagnostics English prefills request detailed context; retain or improve their specificity.
2. BMW transmission: English body already distinguishes maintenance, control faults and internal wear and contains four detailed assessment/verification steps. Add symptom-specific metadata and a structured quotation checklist. Existing WhatsApp prefill is generic. Arabic body currently uses shared translation rather than the English service-specific process, so vehicle identification, service-versus-repair distinction and quote inputs are useful parity improvements.
3. BMW engine: English hero addresses leaks, cooling, lubrication, ignition/fuel/boost paths and supported VANOS/Valvetronic concerns. Existing generic mechanical composer supplies the remaining process and FAQs. Improve repair enquiry context and avoid repeating the hero. Arabic metadata/H1 currently uses generic mechanical repair intent rather than explicit engine repair; a carefully scoped engine-and-mechanical description can align the owner with its existing English intent.
4. Rolls-Royce engine: English override already limits work to supported assessment and expressly excludes electric Spectre from combustion-engine work and universal internal-engine promises. Arabic generic content omits these explicit safeguards. Mirror them in Arabic when strengthening engine-specific explanation. Existing English WhatsApp prefill already asks for model/year/mileage/history/symptoms; Arabic only names the generic service.
5. Rolls-Royce suspension: English override distinguishes model-specific Planar/Flagbearer applicability and does not promise universal calibration. Arabic generic content loses the model-specific scope. Useful improvements are clear reporting of the affected corner, parking duration, warning text and confirmation of the fitted system before quotation.
6. Lamborghini transmission: English override already identifies Huracan EVO LDF, Urus S automatic and Aventador SVJ ISR distinctions, and requires internal repair/rebuild/calibration capability to be confirmed. Arabic generic content omits those scope distinctions. Do not expand compatibility or rebuild claims. Ask for cold/warm engagement/shift conditions and preserve capability confirmation.
7. Lamborghini engine: English override already covers leaks/cooling/noise/drivability assessment and explicitly avoids promising internal engine, hybrid high-voltage or carbon-structure work. Arabic generic content omits these boundaries. Mirror the scope and help enquiries include operating conditions and warning details.
8. Lamborghini engine diagnostics: Existing suitable indexable owner; English copy already covers compatible access, codes versus physical testing, programming limits and booking details. Exact requested query absent from measured demand per analyst; preserve as the diagnostic destination and audit reference, without inventing measured demand or creating another page.

Evidence limitation
Existing reviewed site scope is a conservative content boundary, not independent proof of every workshop capability. No new equipment coverage, component rebuild, certification, dealer status, price, warranty, completion time, programming or high-voltage capability should be inferred. Keep exact-vehicle confirmation for all conditional operations. Local source/layout inspection is not a substitute for post-change mobile browser validation or live indexing verification; those are separate release checks.
