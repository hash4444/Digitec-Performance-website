# DIGI-TEC Mercedes organic improvement — Phase 3

Prepared 26 October 2026. **Read-only investigation and local proposals. No production change was made.** The recommendations protect the existing repair-ranking hub and focus on genuine service evidence, useful customer paths and measurable enquiries. Top-three organic visibility is the objective, not a promised outcome.

## Findings that determine the next work

1. **Keep the existing hub as the owner of the five broad Mercedes queries.** Authenticated, exact-query × landing-page evidence supports it. UAE repair performance is materially stronger than service/workshop/maintenance performance in these small historical samples. There is no evidence supporting a replacement hub, new competing page or title/H1/canonical/URL change.
2. **Review specialist clicks and weaker service visibility without dismantling repair relevance.** The hub received 140 UAE specialist impressions and zero clicks in 28 days at average position 3.4. This warrants snippet, intent and trust review; it does not establish a conversion defect or justify a new specialist page.
3. **Treat body and oil as unresolved URL-variant consolidation questions.** Google’s stored report excludes the slashless body URL but indexes its slash version. The slash version declares the slashless canonical while Google selects the inspected slash URL. Oil has an analogous split. Preserve the current canonical signals and redirects while comparing later stored crawls. Do not describe the entire body-repair service as absent from Google.
4. **The existing content is already substantial.** The hub covers maintenance, repair, scope, quotations, workshop context and relevant internal links. The useful evidence gap is a genuine, approved repair/service record with specific findings and outcomes. Additional generic keyword paragraphs are not supported.
5. **Establish received leads and bookings as separate outcomes.** Existing call/WhatsApp link events and message-draft opens do not prove a received enquiry, qualified lead, booking or revenue. Those outcomes remain unknown without verified collection and workshop/CRM records.

## Body-repair investigation

The current English body page returns relevant **200** for GET/HEAD, one slashless self-canonical, index/follow, crawlable SSR text and sitemap inclusion. The bounded live sample supplies five contextual inbound pages and an Arabic language edge; home → Mercedes hub → body is two anchor hops. The page is not orphaned. The content distinguishes panel/paint assessment, hidden damage, separately confirmed sensors/calibration, quote exclusions and finish checks. Sampled text similarity does not establish a near-duplicate problem.

Google’s stored slashless report still says **Crawled – currently not indexed**, last crawl October 11, successful smartphone fetch, canonical fields N/A and a temporary sitemap-processing message. The slash URL is **indexed**, last crawl July 1, with slashless declared canonical and Google-selected inspected slash URL. The reports are different URL records from different crawl dates. The old sitemap message does not prove the currently reachable XML fails; N/A is not a new canonical or a present noindex directive.

**Most supported interpretation:** current technical eligibility is healthy, while Google’s stored URL consolidation/evaluation remains unresolved. The evidence does not identify Google’s cause. Stale assessment, the existing duplicate slash forms and limited original body-repair proof are hypotheses with different support, not confirmed explanations. The October 11 crawl predates R2 activation; the exclusion cannot be attributed to that redirect from this record.

A desktop browser review confirms relevant content, visible call/WhatsApp choices and an operable first FAQ. The page’s main visual remains a Mercedes logo; no actual accident-repair job gallery was observed. Existing G63 conversion evidence supports that conversion only. Mobile rendering, Googlebot rendering, keyboard/contrast QA and contact receipt were not tested.
