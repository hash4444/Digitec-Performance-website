# Mercedes weekly measurement design

**Design and blank templates only. No performance, interaction, qualified-lead, booking or revenue value is fabricated. No automation, analytics configuration change, live contact, backend inspection or credential access was performed.**

Use one manually produced weekly snapshot with separate **7-, 28- and 90-day** panels and a separately dated **verified organic top-three snapshot** for the six fixed target queries. Keep observed organic rank, aggregate GSC visibility, contact interactions and business outcomes distinct. A search impression is not demand volume, a WhatsApp draft/click is not a received enquiry, a phone click is not a connected call, and neither confirms a booking or revenue.

## Actual GSC baseline and observed coverage limits

The reusable dashboard remains blank by design; actual GSC-only results are in the collector's [paired analysis](../search-console/analysis.md), [daily baseline and comparisons](../search-console/daily-analysis.md), [six-query summary](../search-console/daily-six-query-cohort-summary.json) and [baseline CSV](../search-console/daily-six-query-cohort.csv). Those actual results must not be relabelled as the broader proposed registry, all Mercedes traffic, page all-query totals or business outcomes.

- **Paired periods:** 108/108 exact-query/country/device/window cells validated, containing 328 actual paired Pages rows. Windows are 18–24 October, 27 September–24 October and 27 July–24 October 2026. GSC daily dates use the verified Pacific Time reporting basis; capture timestamps remain UTC with Dubai display.
- **Daily series:** 69/132 accepted: all 36 query-only series (six exact queries × UAE/global × ALL/MOBILE/DESKTOP) and 33 UAE ALL-device exact-query+page series, totalling 6,210 explicit dates. Three attempted series were rejected/rate-limited (429); 60 were unattempted. No accepted exact-page Mobile/Desktop daily series exists. Missing/rejected series are unavailable, not zero, and query-only device rows cannot reconstruct them. See [daily validation](../search-console/daily-ui-validation.json).
- **Observed UAE ALL-device six-exact-query baseline:** current 7 days **0 clicks / 146 impressions**, preceding 7 **4 / 247**; current 28 **5 / 849**, preceding 28 **3 / 945**; 90 days **14 / 2,769**. The six mutually exclusive exact query strings and source references are retained in the baseline files. Prior 90 days is unavailable. The accepted 90-day series can supply preceding 7/28-day comparisons only at the same collected grain; do not invent missing page/device series or prior-90 history.
- **Canonical evidence:** eight fresh stored inspections were accepted. English body slash URL is indexed with Google selecting that inspected slash URL, despite a slashless declared canonical, based on a 1 July crawl; slashless body remains Crawled – currently not indexed from 11 October with canonical fields N/A. English oil has the analogous stored slash/slashless divergence. See [accepted indexed observations](../search-console/indexed-observations.json) and [body interpretation](../indexing/README.md). These are stored crawl records, not fresh Google crawls; N/A is not a missing current HTML canonical. Preserve current public signals while reviewing convergence read-only.

All performance data ends **24 October**, before the 26 October redirects. It cannot establish their recovery effect. Actual source zero rows remain numeric zero; displayed em-dash CTR/position remain null. Daily display positions are rounded, so impression-weighted reconstruction is approximate. No GA4 event count, qualified lead, booking, attributed revenue or deterministic join has been established by these GSC exports. No canonical, title, routing, sitemap or index change is recommended or performed by this measurement design.

## Time and cohort contract

For a run, first identify **D**, the latest complete final GSC source-report day available and documented by the collector. For each N in 7/28/90, current window is D−(N−1) through D inclusive; previous is D−(2N−1) through D−N. Use the same endpoint D and exact source settings for every panel. A 90-day-versus-prior-90 comparison needs 180 days; leave the comparison unavailable if history is missing. The three overlapping windows must never be added together.

Record the GSC report timezone as supplied/verified by its owner, GA4 property timezone and CRM/finance source timezone separately. Display operational run timestamps in UTC and Dubai. Do not silently relabel source days as Dubai days or force daily joins across incompatible timezones. Reuse the same source calendar windows for comparisons; disclose any cross-source date boundary difference. Late CRM stages/credits and revised exports get a new snapshot version and explicit as-of time.

Country `ARE`/UAE describes the source report's country dimension; it is not a Dubai-local SERP measurement. Average GSC position is an aggregate observation, not a guaranteed fixed rank, local-pack rank or device-independent ranking. Retain missing/suppressed query cells as unknown. Device and country must come from the source, not the page language or a staff guess.

## Attribution and privacy boundary

GSC aggregate queries cannot be joined to an individual GA4 user, enquiry or invoice. Cross-source search/interaction comparisons use compatible **cohorts**, not individual search-query attribution. Preserve raw source URLs in their access-controlled original export; the derived dashboard uses `page_url_sanitized` without query/fragment, a source reference, normalised path and separate migration-family label. Do not merge slash variants or legacy URLs before preserving their evidence, or place sensitive raw queries into this dashboard.

Current frontend attribution stores a session-scoped first touch with sanitised landing URL/referrer and allowlisted `utm_source`/`utm_medium`. It does not establish a persistent interaction→CRM join. Do not add UTMs to internal links, tag organic search traffic as paid, or assume query preservation means analytics/CRM retained a click ID. Arbitrary campaign/content/search terms are deliberately omitted by the current source.

A future join, only after separate approval, should use an opaque interaction/reference token and deterministic `interaction_ref → lead_ref → booking_ref → invoice_ref` mapping. Keep that map restricted; do not hash names/phone numbers as a substitute. An optional advertising click-ID reference may be retained only where actually available, permitted and required; use a restricted opaque reference, not raw gclid/gbraid/wbraid or customer data in this dashboard. No such token, click-ID bridge or CRM integration was implemented here.

Never put names, customer phone/email, WhatsApp message text, VIN, registration, precise location or full URL queries/fragments into dashboard exports, analytics parameters, public reports or join keys. Keep operational customer data in its existing restricted system. Assign a named business data owner to set access, retention and deletion before any new join collection; this design grants no new access. Report consent/collection gaps and deterministic attribution coverage rather than filling them with assumptions.
