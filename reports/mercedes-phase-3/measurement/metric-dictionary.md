# Metric dictionary

All metrics require a source reference, extraction/as-of timestamp, date window, source timezone, dimensions, acquisition/country/device filters and completeness status. `null` means unknown/unavailable/suppressed; a numeric zero is permitted only when an actual complete source reports zero. Do not calculate percentage changes from a zero or unknown comparator; show the absolute delta and “not comparable.”

| Metric ID | Definition / calculation | Source, scope and interpretation |
| --- | --- | --- |
| `gsc_clicks` | Sum source-reported clicks for the exact frozen cohort. | GSC Web source/settings fixed; query/page/country/device rows are a separate view from property controls. Avoid adding overlapping extracts. |
| `gsc_impressions` | Sum source-reported impressions for the same cohort. | Visibility observations, not search volume or unique people. Query privacy/row limits can omit rows. |
| `gsc_ctr` | `Σclicks / Σimpressions`; undefined if impressions are zero or unavailable. | Store a fraction; display percent. Never average row CTRs. |
| `gsc_average_position` | Source aggregate or, for disjoint compatible daily rows only, `Σ(position × impressions) / Σimpressions`. | Same GSC aggregation/dimensions throughout; never unweighted average positions, combine property/page aggregation, or label as fixed Dubai rank. |
| `organic_top3_observed_query_share` | For the six fixed exact queries at one documented Dubai/UAE device/language/location context: manually validated query checks with a verified DIGI-TEC URL in the actual first three eligible headed organic web results / all manually validated query checks. Show validated coverage / six planned queries alongside the latest snapshot. | Exclude sponsored, maps/local packs, AI/features, owner panels and sitelinks before counting three top-level headed results. Save the three actual URLs and raw/context evidence per query. Missing/unverified checks are unknown, not misses. Do not infer a numerator from GSC averages or an unverified SERP extraction. Device contexts remain separate; a location parameter/colo is not independent UAE-client proof. |
| `gsc_avg_position_le3_proxy_share` | Positive-impression returned fixed queries with GSC query-level average position ≤3 / all positive-impression returned fixed queries at the same property/country/device/window. | Explicitly an aggregate-position proxy, not organic top-three share. Preserve missing/suppressed query coverage. It cannot establish the first three current web results or local-pack position. |
| `target_query_top10_observed_share` | Returned target queries with positive impressions and average position ≤10 / all returned target queries with positive impressions, using the query-level property control for the same country/device window. | Deduplicate queries through that control, not query×page rows. Descriptive observed-query coverage; missing/suppressed queries are unknown, not rank 100. Show observed query count / full frozen registry count separately. Not a SERP rank-tracker or local-pack metric. |
| `mercedes_page_clicks` | All-query GSC clicks for the exact Mercedes page cohort, with no query dimension. | Preserve raw reported page URL and migration family. Report owned hub, service and legacy aliases separately before any family rollup. |
| `mercedes_page_impressions` | All-query GSC impressions for that page cohort. | A query-filtered cohort has a different denominator; do not substitute it. |
| `mercedes_page_ctr` | Page-cohort clicks / page-cohort impressions. | Never sum page totals and their query rows. Returned-query totals need not reconcile to page controls because of source privacy/aggregation limits. |
| `organic_mercedes_landing_sessions` | Collected sessions with an in-cohort Mercedes landing page and verified Organic Search acquisition definition. | GA4 export only. Record the exact acquisition dimension/scope and property timezone; first-touch custom fields are not automatically session attribution. Clicks and sessions need not equal. |
| `telephone_link_interactions` | Count collected `telephone_link_clicked` events on in-scope pages; optional landing cohort separately. | Existing source event, delivery/counts unverified. An event count is not unique callers or connected calls. |
| `whatsapp_anchor_interactions` | Count collected `whatsapp_chat_opened` anchor events. | Do not add dataLayer `whatsapp_click` for the same action. Attempted navigation, not a received message. |
| `whatsapp_draft_attempts` | Count collected `whatsapp_draft_opened` events, with brand/page/form scope. | Existing source event, delivery/counts unverified. The Mercedes form is scheduled-maintenance intent, not proof of a repair enquiry or booking. |
| `contact_interactions_total` | Telephone + WhatsApp anchor + WhatsApp draft event counts after confirming mutually exclusive action taxonomy and removing duplicate collection. | An action count only. One person may generate multiple interactions; never use it as the count of distinct qualified leads. Email/directions may be a separate panel, not added silently. |
| `organic_contact_interaction_rate` | Organic Mercedes landing sessions with ≥1 validated contact event / all such sessions. | Requires session-level export/approved join. If unavailable, show counts only; do not divide all-page clicks by organic landing sessions. |
| `received_mercedes_enquiries` | Distinct CRM `lead_ref` created in the period after a message/call is actually received, Mercedes intent confirmed, repeats merged and spam excluded. | Workshop/CRM source of truth. Unknown brand/intention goes to an unresolved queue, not silently into Mercedes. |
| `qualified_mercedes_leads` | Distinct received `lead_ref` with a genuine Mercedes service/repair need, sufficient vehicle/contact context for a response, relevant workshop scope and staff-confirmed qualification. | Business owner approves the exact rule and reason codes; pricing browsers/spam/duplicates are not automatically qualified. No customer PII leaves the operational system. |
| `qualified_enquiry_rate` | Qualified leads from the period's received-enquiry cohort / all received enquiries in that same cohort, evaluated at recorded as-of time. | Requires linked stage history. Status maturity/lag disclosed; do not divide unrelated qualification-date counts by enquiry-date counts. |
| `confirmed_bookings` | Distinct `booking_ref` confirmed in the period by the workshop with agreed scope/date and linked `lead_ref`; cancellations shown separately. | Workshop booking register. “Prepare WhatsApp draft,” appointment preference and quote acceptance alone do not confirm a booking. |
| `qualified_to_booking_rate` | Qualified enquiry cohort with ≥1 confirmed noncancelled booking as of cutoff / distinct qualified leads in that cohort. | Cohort conversion separate from bookings-confirmed-during-period count. One lead's multiple bookings do not increase this numerator beyond one. |
| `cancelled_bookings` | Distinct confirmed bookings cancelled in the period; record confirmation cohort separately. | Do not silently subtract historic cancellations from an unrelated current booking cohort. |
| `attributed_net_revenue_aed` | Sum finance-approved posted net invoice amounts less applicable credits/refunds, excluding VAT under the agreed definition, linked once through invoice→booking→lead to a deterministically supported organic Mercedes acquisition. | Finance approval required. Invoice date-period revenue and lead-cohort eventual revenue are different panels. Quotes, deposits, gross billings and cash receipts are not interchangeable. Report booked versus recognised/cash values separately if needed. No values available here. |
| `deterministic_attribution_coverage` | Business outcome records with approved deterministic acquisition join / all in-scope records for that same outcome cohort. | Report leads/bookings/revenue coverage separately. Self-reported “Google” or unmatched cases remain labelled and excluded from deterministic attributed totals; they may be shown separately. |

## Weekly comparison rules

Use current versus immediately preceding nonoverlapping 7/28/90-day windows from the same final day D, with the same frozen query/page registry, country/device filters, source settings and aggregation. Retain raw query spelling and raw page URLs. Registry normalisation is a lookup aid, not permission to relabel a returned query or infer an unobserved URL.

For exact target visibility, show **query × every observed page × UAE × mobile/desktop**; keep tablet and all-device control rows. A query can appear on an unexpected page; do not force it onto the planned owner. The planned owner is a separate registry field. “Mercedes” is a vehicle-brand topic; distinguish queries mentioning Digi-Tec/business brand from broader Mercedes service queries without reclassifying either as measured demand.

Dashboard notes must list exports that were partial, suppressed, truncated, unavailable or not comparable; all-query GSC controls versus returned-query coverage; GA4 collection/consent gaps; unregistered parameters; uncertain first-touch versus session scope; unmatched CRM/finance records; and late-stage/invoice revisions. Do not join GSC query rows to an individual contact or manufacture lost historical attribution.

The actual first [daily baseline](../search-console/daily-analysis.md) uses six mutually exclusive exact queries at one country/device/date/property grain. It supports that cohort's additive clicks/impressions and recomputed CTR, not all-Mercedes/page all-query totals. Only accepted exact-page series may be used for a page-specific daily metric; 33 UAE ALL-device pairs are accepted, while exact-page Mobile/Desktop series are unavailable. Accepted query-only device series cannot supply the missing page dimension. Current/prior 7 and 28-day slices exist within accepted 90-day series; prior 90 days is not available. Display-rounded daily positions yield approximate weighted positions, and all current performance windows end before the 26 October release.

Organic SERP checks have their own capture clock. The latest six-query snapshot belongs in the separate snapshot block; a 7/28/90 period metric may include only validated checks actually captured inside that window, with constant context and an explicit query-check denominator. Do not place a 26 October SERP snapshot into GSC windows ending 24 October, infer historic organic rank, combine desktop/mobile into one rank, or use repeated checks without unique capture/query/device references. No manually verified top-three numerator is populated by this package.
