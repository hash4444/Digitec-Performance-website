# Manual weekly runbook — no automation created

Choose a consistent weekly review day with the business owner. This is a repeatable procedure, not a scheduled task. Use the exact latest source evidence; no website/configuration mutation, live WhatsApp message, call, indexing action or credential creation is needed.

The first actual GSC source baseline is [daily-analysis.md](../search-console/daily-analysis.md) with [six-query values](../search-console/daily-six-query-cohort.csv), ending 24 October 2026. It is six exact queries, not all Mercedes. Current accepted coverage is 108 paired period cells and 69/132 daily series (36 query-only plus 33 UAE ALL exact-page; 6,210 dates). Three attempted series were rejected/rate-limited and 60 unattempted; exact-page Mobile/Desktop daily rows and prior-90 history remain unavailable. Retain those limits in any weekly snapshot rather than filling gaps from differently aggregated data. The blank templates remain reusable design artifacts, not measured results.

1. **Open a new versioned local snapshot.** Record run ID, owner, UTC/Dubai capture time, source timezones, source export names/hashes, registry version and as-of time. Preserve earlier snapshots; never overwrite the Phase 2A failure or raw measurement exports.
2. **Set complete windows.** Confirm the collector's latest complete final GSC day D. Use D−6…D, D−27…D and D−89…D, with paired preceding windows. For 90-versus-prior-90 request 180 complete days or mark the comparator unavailable. Document the GA4/CRM date-boundary difference rather than relabelling source timezones.
3. **Obtain read-only GSC evidence.** Use the existing verified property and the Phase 3 collector's approved export/API workflow. Capture query×page×country×device, query-level controls and page all-query controls separately; retain source search type, dimensions, aggregation, finality, pagination and row coverage. API Web and UI text-based/all-tabs reports must not be assumed equivalent. No request for indexing or live inspection is part of this dashboard task.
4. **Apply the frozen registry locally.** Select exact target queries without forcing planned owners. Preserve all observed pages, country/device dimensions and missing/suppressed cells. Report UAE mobile/desktop separately, retain tablet and all-country/all-device controls, and group legacy aliases only through the separate migration label. Missing rows are not zero or proof of no demand.
5. **Obtain existing GA4/GTM read-only exports.** Analytics owner confirms delivery of the source event names, property timezone, acquisition scope, parameter availability, data-quality notices and possible double collection. Export page/landing and event views for the same calendar windows. Do not change tags, key events, consent settings or custom definitions merely to fill missing cells. Existing dataLayer and gtag WhatsApp signals may be one action; do not add them together.
6. **Obtain restricted business-outcome exports.** Workshop owner supplies anonymised received/qualified enquiry, booking and cancellation stage records; finance supplies approved invoice/credit amounts and references. Keep names, customer contact details, VINs, registration and free-text messages in their existing operational system. Empty/unavailable exports stay unknown.
7. **Validate joins and arithmetic.** Deduplicate opaque references; distinguish received contact from draft attempt. Verify approved interaction→lead→booking→invoice matches only where evidence exists. Keep unmatched/self-reported attribution separate. Recompute CTR from totals, position from compatible impression-weighted rows, and conversions from the same dated cohort with an as-of cutoff. Check one-to-many invoices/credits and never count an invoice twice within a panel.
8. **Fill the blank dashboard.** Populate `dashboard-template.json` only from actual evidence, keeping availability/reasons/source refs per metric. Leave `null` for unavailable/suppressed values and undefined denominators. Show 7/28/90 panels side by side; never sum their overlapping totals. Display observed-query coverage, data freshness, attribution coverage and reconciliation exceptions prominently.
9. **Business review.** SEO owner explains visibility/page-CTR changes without promising ranking recovery. Workshop owner validates lead quality/bookings; finance validates revenue. Distinguish a technical redirect regression from ordinary short-term search movement. Current GSC canonicals/indexing need a separately authorised read-only inspection; HTTP eligibility alone does not settle them.
10. **Record actions without executing changes.** Each action needs an owner, evidence, expected impact, risk, dependency, verification and approval boundary. A recurrent redirect miss should retain exact URL/method/time/CF-Ray/headers/body; it is not authority to edit rules or purge caches. Any new tracking, CRM join, content deployment or recurring automation is separate implementation requiring the user's instruction.

## Explicit organic top-three check at the manual weekly review

Use the six fixed exact strings: **mercedes service dubai, mercedes repair dubai, mercedes specialist dubai, mercedes workshop dubai, mercedes maintenance dubai, mercedes oil change dubai**. Keep Dubai/UAE location method, observed location label, language, browser/login context and actual desktop/mobile device or clearly labelled emulation consistent; record UTC/Dubai capture time and device context separately. Use available authorized read-only search access; unavailable contexts stay unknown.

For each query/context, preserve a full visible result capture and the actual URLs/blocks. Manually exclude sponsored blocks, maps/local packs, AI/knowledge features, owner-only panels and related links. Count the first **three eligible top-level headed organic web results**, treating sitelinks as part of their parent rather than separate ranks. Verify whether an actual DIGI-TEC URL is in those three. Record a unique capture/query/device reference, all three URLs, classification and reviewer; retain at least three eligible results before declaring a validated miss. Missing/incomplete/unclassified captures do not become zero or “outside top three.”

Calculate observed top-three query share only from validated checks and show validated coverage out of six planned queries for each latest device/context snapshot. Initial competitor captures may be reviewed as an optional starting source, but no numerator is inferred automatically. The latest snapshot is separate from dated GSC panels; only checks captured within a period can populate that period's SERP metric. GSC average position ≤3 stays the separately labelled proxy, never proof of the primary organic top-three objective. This is a bounded manual procedure; no monitoring automation or schedule is created.

## Source ownership and sign-off

| Owner role — named person to be assigned | Accountable for | Must not infer |
| --- | --- | --- |
| SEO/report owner | GSC registry, source exports, window/filter consistency, query/page coverage and written interpretation. | Search volume, fixed local rank or conversions from impressions. |
| Analytics/tag owner | GA4/GTM read-only definitions, event delivery/deduplication, acquisition scope, timezone and collection limitations. | Existing source code proves delivery or historic missing fields can be reconstructed. |
| Workshop/CRM owner | Received enquiry, qualification reasons, deduplication, confirmed appointments and cancellations. | A CTA/draft proves a lead or a booking. |
| Finance owner | Invoice/credit treatment, AED revenue reconciliation and approved joins. | Clicks/quotes equal recognised revenue. |
| Business data owner | Access, retention, permitted join identifiers and any proposed collection approval. | This template itself grants new access or permits customer identifiers in analytics. |

The weekly output is a dashboard JSON/Markdown snapshot, raw export hash manifest, reconciliation notes and an action backlog. Source systems remain authoritative; the dashboard is a derived view.
